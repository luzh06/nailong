# 拍照模块审改记录：东京 · 悉尼

每轮做法：在 Claude 应用内置浏览器里打开 `photo-test.html`，用测试页的“去这里”参考机位真实取景、按快门，
把照片、纪念章、回忆卡存成文件后逐张看图，写下最差的三个问题，改，再拍一遍验证。
颜色一致性的量法：关掉相机风格（不加颗粒、暗角），同一机位比较“取景框里那一块屏幕”和“拍出的照片”，各缩到 512 像素再分 8×8 块求平均差（0—255）。

---

## 第一轮（2026-11-03）

拍了东京 7 个、悉尼 7 个打卡点，加东京回忆卡和 7 枚车站章。打卡判定 14 个都过了，但看图发现：

### 最差的三个问题
1. **凑近拍局部也算盖章。** 占比是按“主体包围盒裁到画面里的面积”算的，凑得很近时只拍到大提灯的下半截也算 100%。
2. **取景框提示不跟状态，视觉也不像书页。**
   - 已经加了 +2/3 EV，提示还在说“按 ↑ 加 2/3 档”。
   - 凛用的即时成像是方画幅、没有横竖之分，提示却叫人“竖拍（R）”。
   - 地点名是黑色半透明牌子，和“纸、墨、朱红”的书页语言不搭。
   - 打卡时胶片旁轴亮框的四角只是略微变黄，不明显；方框变暖时外面还叠着四角，成了双线。
3. **纪念章和回忆卡的细节。**
   - 章面上的白点是一格一格的方块像素，一看就是电脑做的。
   - 回忆卡上的章挤在左下角，又小，字看不清。

### 改了什么
1. 新增“露出比例” `minVisible`：主体投影里至少一半（默认 0.5）要在画面内。
   - 夕焼けだんだん拍的是“从台阶顶往下看的那一眼”，台阶本身大半在画面外，单独放宽到 0.05。
   - 大提灯的参考机位往后退了 3.5 米。
   - 验证：凑近只拍到提灯下半截时，露出比例 0.10，不算；参考机位 0.94，算。
2. 提示可以写成函数，按当时的曝光、横竖、低角度给不同的话。
   - 加过曝光后，T4 显示“第一次日落”。
   - 方画幅不再提“按 R 竖拍”，胶片旁轴横拍时才提。
   - 剧情必拍点优先于可选点：白天站在台阶顶，显示“夕焼けだんだん · 等日落时再来”，不再被远处的电线杆抢走提示。
   - 地点名改成夹在框里的纸签：纸色底、墨色字、左边一道朱红；时段不对时变灰。
   - 打卡时亮框四角变朱红并加粗加长；方框整圈变朱红，去掉叠加的四角。
3. 章面白点改成大小不一的圆点，加一层平滑的淡颗粒。回忆卡上的章改成居中、加大、错落叠放。

## 第二轮（2026-11-03）

量了两城三个时段的颜色一致性，看了悉尼的步道章和两张回忆卡（悉尼 3 张横幅照片、东京 7 枚章）。

### 最差的三个问题
1. **对着太阳拍时，照片的光晕比取景时小。** 悉尼黄金时段对着落日，块平均差最大 9.4/255，东京也有同样的根源。
   - 原因：拍照时泛光按“整个屏幕的高度”算，可照片对应的只是取景框那一块（屏幕高度的 80%）。
   - 悉尼那条 EffectComposer 还会按屏幕 4:3 的宽高比算泛光，照片却是 3:2，光晕形状也不一样。
2. **回忆卡版式。**
   - 3 张横幅照片时，大图和下面两张之间空了一大块，下排又贴着说明文字。
   - 集齐 7 枚章时，挤成一串互相压着，还压到纸边。
3. **悉尼步道章的图案。**
   - 长椅画成了正面的横杠，像栅栏。
   - 歌剧院和大桥的图案自带一道波浪，和牌子本身的波浪线叠成两道。

另外发现：从步道看海港大桥（约 500 米远，连引桥一千多米），什么焦段都装不下“一半”，新加的露出比例让大桥拍不到章了。

### 改了什么
1. 拍照时把“取景框在屏幕上的像素高度”（`screenHeight`）传给画面管线，两条管线的泛光都按它算，宽高比用照片的。
   - 悉尼黄金时段：最大差 9.4 → **1.45/255**，平均差 1.3 → 0.26。
   - 东京白天、日落：最大差都在 **1.6/255** 以内。
2. 回忆卡“一大两小”改成按实际高度排紧，整组上下居中；5 枚章以上排成错开的两行。
3. 长椅重画成斜侧面（三根靠背板条、两根座板、铸铁扶手）；去掉歌剧院、大桥图案里多余的那道波浪。
4. 大桥单独设 `minVisible: 0`。拍全景（28mm）或拍一段拱（85—135mm）都算，仍要求桥的中心在画面里、占比 ≥ 6%。

### 验证
- **颜色**（块平均差 0—255，最大值）：

  | 场景 | 最大差 |
  |---|---|
  | 东京白天 | 1.56 |
  | 东京日落 | 1.61 |
  | 悉尼白天 | 1.82 |
  | 悉尼黄金时段 | 1.45 |

  - 悉尼蓝调最大 17：差异全在写字楼窗户这种比像素还细的贴图上。照片 3000 像素能分辨出更多窗格，取景时 1800 像素分辨不出，属于清晰度不同，不是偏色（整体平均差约 2/255 以内）。
  - 剩下的差异都在物体边缘，约 0.2% 画幅的亚像素错位，肉眼看不出。
- **悉尼焦段**：步道上看歌剧院（约 1 公里），各焦段的占比如下。门槛是 4%，所以要 85mm 以上，和“135mm 拉近”的设计一致。

  | 焦段 | 占比 |
  |---|---|
  | 28mm | 1.0% |
  | 50mm | 3.3% |
  | 85mm | 9.6% |
  | 135mm | 24% |

- **东京焦段**：店面用 35mm 横拍，从对街拍店门露出 0.86—0.87；24mm 能在台阶顶装下整条街加夕阳。
- **竖拍和低角度**：胶片旁轴竖拍、24mm、低角度拍五重塔，照片 2000×3000，元信息 `portrait / lowAngle: true` 正确。
- **剧情行动**：关掉“剧情行动已完成”后拍遥的店，只发 `stampwait`、不盖章；打开后正常盖章。
- **两张回忆卡**：悉尼三张横幅照片排紧了；东京七枚章排成两行，没压纸边。

## 还没验证
- 没接真实东京、悉尼场景（东京烘焙包约 477MB，本机放不下）。打卡点的占比门槛是在占位几何上定的，接真场景后要按真模型的包围盒再拍一遍，可能要调 `minCoverage` / `minVisible` / `radius`。
- 夕阳方向是按 `game.js` 的 `LIGHT.sunset` 算出来的，没在真场景里对过。
- 悉尼三个时段的曝光、泛光数值是测试页的兜底值，悉尼工程有自己的光照代码，以它为准。
- 测试时内置浏览器面板处于隐藏状态，界面的过渡动画没法逐帧看；取景框样式是读计算后的样式确认的（朱红框 3px 等），截图里能看到纸签的样子。

# 此间｜Agent执行手册

版本：0.9｜2026-11-01  
用途：给Claude、Codex或接手成员读取的项目上下文与交接约定。  
先读：[两日项目规划书](./此间_两日项目规划书.md)，再读：[任务清单与工作流](./此间_任务清单与工作流.md)。

> 当前阶段仅已生成规划文件。未获得已有MVP的源码和路径，未验证任何业务功能。下面的模块、目录和数据字段是推荐契约，实施前须映射到真实工程。不得凭本手册声称已经完成代码或部署。

## 1. 项目事实与不可擅自改变的目标

- 项目：此间；团队暂用名：三径；三名成员、三台电脑、两天。
- 主办方允许独立网页等互动作品。默认电脑端网页，优先延续现有MVP。
- 核心目标：身临其境地探索发现，认识真实地点的文化与生活。
- 首发建议：杭州西湖南岸的艺术化文化旅行；最终由团队在G1选择。
- 美术：经过审美化处理的写实电影感，重视真实地貌与建筑细节。
- 核心：自由行走、拍照、天气、早到晚的体验、轻任务选择、个人回忆卡。
- 首发范围建议：1世界、3个相连场景、2条轻主线共享场景、晴／小雨、4时段、2个傍晚收束。
- 目标时长：快速2—3分钟、完整10—20分钟；以陌生试玩结果校准，不伪造时长。
- 人物和短句可离线配置；不把实时AI请求放在基础体验的唯一通路。
- 已有MVP由另一位队员使用Claude制作，用户不知道技术栈。本Agent需要先取得实际工程信息。

团队尚未确认的决定：具体地点、真实交付时刻、现有技术栈与目录、实际设备能力、成员A／B／C姓名、协作方案。不要用主观猜测补成事实；按照任务A01、B02、C01核验后记录。

## 2. 第一次接入工程时的动作

1. 阅读项目真实的README、AGENTS、依赖清单和现有运行说明。
2. 找到已有入口、渲染器、移动、场景、状态、截图相关代码；记录现状，不先重写。
3. 用工程现有命令运行一次，记录实际成功或错误。未知命令先查配置，不按本手册虚构。
4. 确认改动前的可回退版本，尊重已有未提交改动。
5. 将推荐模块映射到实际文件；在整合记录中登记路径和所有权。
6. 领取一个具体任务ID，说明输入、输出、预计修改范围与验证方式，再实施。

现有栈已经可用时，不因为偏好改成另一个框架。不要让另一个模型同时重建入口、全局状态或依赖。

## 3. 三人及Agent的职责

| 角色 | 主要负责 | 允许决定 | 需共同确认 |
|---|---|---|---|
| A 系统与整合 | 工程、状态、移动接入、真实截图、存档、构建、发布 | 小范围工程实现与合并顺序 | 栈迁移、核心删减、上线资源支出 |
| B 世界与视觉 | 资产、地形、建筑、材质、环境预设、机位、优化 | 冻结方向内的视觉细节 | 城市改选、地标形制变化、超预算资源 |
| C 文化与体验 | 文化来源、任务、对白、界面、回忆卡版式、试玩和演示 | 冻结范围内的内容与引导 | 新增主线、文化主张、展示承诺变更 |

Claude与Codex都可担任实现者或审查者，不按模型名称固定权力。每项任务只有一个主写者，审查者先给问题和证据；需要修复时明确由谁修改。代码改动按项目适用要求进行审查，不把同一模型生成后自评视为唯一验证。

## 5. 最小数据契约

由A在A02依据真实工程定下类型与实现。以下字段需在同一套状态中表达。

### 5.1 旅行状态

| 字段 | 意义 | 基本限制 |
|---|---|---|
| schemaVersion | 存档结构版本 | 读档先检查兼容性 |
| worldId | 当前实际开放世界 | 筹备中世界不可进入 |
| mode | quick／full | 两种模式分别保存 |
| routeId | 寻景／访俗等路线 | 开始后变更要处理已有进度 |
| sceneId | S01／S02／S03等实际场景 | 不允许不存在的ID |
| phase | morning／afternoon／sunset／night | 按事件推进，不凭界面私自修改 |
| weather | clear／rain | 切换不清除任务 |
| visitedNodes | 已访问地点集合 | 节点重复访问不破坏状态 |
| completedTasks | 完成任务集合 | 幂等，重复点击不重复推进 |
| endingChoice | 傍晚选择 | 卡片和读档使用同一值 |
| pose | 安全位置与视向 | 无效位置回到安全节点 |
| photoRefs | 本机实际照片记录引用 | 不假定另一台电脑可读取 |

### 5.2 内容配置

每个任务记录：ID、所属世界／路线、发生节点、前置事件、显示提示、完成事件、后续阶段。每段对话记录：角色、短文本、可跳过行为、关闭行为、发送事件、文化来源ID。每个机位记录：地点ID、推荐位置、视向、可选构图提示。

回忆文本使用路线、实际完成事件和结尾选择映射；不能只随机生成与经历无关的句子。

### 5.3 照片记录

照片ID、实际图像Blob或本机持久化键、地点ID、拍摄阶段、天气、镜头／视向、创建顺序。只存可序列化的元信息；临时对象URL不能被误当成永久跨会话地址。

照片最多3张进入首发卡片。用户改选图片时不改变对应的拍摄元信息；应用退出后按持久化策略恢复，不能只恢复一串已经失效的地址。

### 5.4 事件与规则

开始体验、选择路线、完成任务、切换天气、请求下一阶段、拍摄完成、选择结尾、导出回忆、继续节点、重开。

执行原则：

- UI发送事件，世界、内容和卡片消费同一个状态。
- 主线前置条件不满足时，有可理解的引导，不无响应。
- 跳过旁白等价于省略播放，不等价于跳过必要状态更新。
- 界面出现时协调鼠标／键盘控制，关闭后恢复。
- 真实截图与卡片导出使用同一照片数据，不各自放一张预制图。
- G2可先实现这份契约的最小子集，G4前接入完整状态；不要另写一套假演示流程。

## 6. 给A的启动提示词

> 你负责《此间》的系统整合。先读取真实工程、AGENTS与README，复现已有MVP，记录入口、运行命令、技术栈与可用功能。当前只做任务A01、A02、A03，不重写整个项目。已有成员与Agent也在工作，请勿回退或覆盖他们的改动。你拥有入口、状态契约、依赖与构建配置的修改权；与B、C约定文件边界。优先验证一次真实场景截图可打开，并给出后续接入卡片的数据约定。输出：实际路径与运行结果、文件映射、状态／事件契约、截图证据、阻塞和下一项任务。未经核验不声称完成。不要替团队购买资源或擅自切换城市与核心范围。

## 7. 给B的启动提示词

> 你负责《此间》的世界与视觉。先读总方案、实际工程映射和文化参考，执行B01—B03。首发默认候选杭州西湖南岸，另选一个已有资产明显占优的候选做有限比较。用运行小样判断，不只交概念图。视觉目标是审美化写实电影感、地理关系和地标细节可信。交付一个可导入的小场景、真实运行截图、来源／许可、季节与光照参考、推荐机位、场景坐标和碰撞边界。你不拥有入口、锁文件和全局状态；如需改变接口先与A确认。你不是唯一协作者，不覆盖他人的改动。每次只增加可验证的小块，不制作多个完整城市。

## 8. 给C的启动提示词

> 你负责《此间》的文化、内容与体验。先读总方案和实际契约，执行C01—C05。目标是让玩家通过观察、交流和轻互动认识一个真实地方，不能把文化内容做成无依据符号拼贴。整理4—6条有来源的事实，明确传说和原创。设计S01—S03两条共享场景的轻主线，定义前置事件、关闭／跳过行为、傍晚选择和回忆卡映射。先给G2一个使用实际照片的极简版式，后续再细修。你负责内容与UI，A负责全局状态和截图底层，B负责世界与资产。你不是唯一协作者，不回退他人的修改。输出内容配置、短对话、卡片版式、事实来源和接入说明，避免未运行就宣称可体验。

## 9. 给审查Agent的提示词

> 只审查当前任务范围，不重写工程。先看任务ID、变更、契约与运行证据。检查：是否覆盖任务验收；是否存在状态分叉、事件重复、截图黑图／预制图冒充、存档引用失效、文件所有权冲突、文化无来源、未完成世界误导、主路径不可访问、资源失败被吞掉。区分必须修复和建议优化，给出具体文件与复现方法。没有发现问题就明确说明审查范围与未验证部分。不要把自己的推测写成已实测结果；不要因为审查顺便改动其他成员文件。

## 11. 遇到问题时

先读完整错误与当前配置，提出一个可以验证的原因，做最小改动并复测。连续两次同类尝试无效时，换取完整错误、相关文件和运行条件，不继续凭截图猜测。不在同一次修复里同时换框架、改依赖、改渲染设置和重做资产。

遇到模糊需求，优先查团队决策记录与状态契约。涉及城市、两主线、天气、自由行走或拍照等核心变更，给出原因、影响和替代方案，让团队记录决定。可逆的局部实现按职责推进，不为每个小参数重复要求确认。

## 12. 最后一天的执行约束

T12冻结功能范围，T14后不新建系统，T16后只修交付阻塞和严重问题。新增一个效果前，先确认不会破坏现有移动、照片、卡片与存档。最后一轮回归用陌生会话与实际设备，不只在作者热缓存的开发页面看一眼。

手机端完整游玩、云相册、实时AI自由对话、多世界同时上线都属于后续范围。若团队另行决定加入，必须同时删减等量工作并更新展示承诺，不能仅在提示词里无限加功能。

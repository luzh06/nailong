# 《此间》拍照功能：调研交接

写于 2026-11-02，由 5070 本机 Claude 整理，给继续研究拍照、相册和回忆卡的队员及其 Claude。

**这份文档是什么：** 一份方案调研，不是已定设计。文中凡写“建议”的，都还没有经过团队确认；写“已定”的，出处都标在后面。**目前还没有写任何拍照代码。**

**开工前先读：** 第 1、2 节（哪些已定、哪些待定），再看第 3 节的方案。

## 3. 建议方案（尚未确认）

整条线：**取景 → 快门 → 存照片 → 打卡集章 → 相册 → 回忆卡**。

### 3.1 取景模式
- 按 C 或右键进入，所有 HUD 隐藏，只留取景框、三分线和水平仪。
- 焦段做成 24 / 35 / 50 / 85mm 四档定焦，滚轮切换。比无级变焦更像真相机，也更好调画面。
- 点画面对焦：用射线测出点中位置的距离，设为景深焦点。在 5070 上，景深是让画面“像照片”最明显的一步。
- 胶片风格 3—4 种，默认跟时段走（晨偏冷、暮偏暖），玩家可以换。
- 进入取景时，走路输入要暂停；退出后恢复（对应 `two-day-plan.md` 第 9 节第 4 条）。

### 3.2 快门和截图
- 快门叶片合上再打开，加快门声。同一套动画以后直接做“快门转场”，一次做两用。
- **截图做法：** 不抓屏幕画布，而是把当前相机渲染到一张约 3000 像素宽的离屏渲染目标（`WebGLRenderTarget`），读回像素后转成 Blob。好处是出图比屏幕清晰，也不用全局开 `preserveDrawingBuffer`，同时避开规划书提到的黑图问题。
  - 如果先走简单路线：在同一帧里 `renderer.render()` 之后立刻 `canvas.toBlob()`，也能拿到正确画面。
  - 截图前要隐藏取景框等 DOM 元素；DOM 本来就不在 WebGL 画面里，但要确认 3D 场景里没有提示用的物体（比如打卡点标记）。
- 每张照片的元信息建议：

  ```js
  {
    id, createdOrder, createdAt,
    sceneId, spotId,            // spotId 为空表示自由拍摄
    phase, weather,             // 拍摄时的时段、天气，之后不改
    camera: { position: [x,y,z], quaternion: [x,y,z,w], focalMm, focusDist, look },
    blobKey                     // IndexedDB 里图片的键
  }
  ```

  `camera` 这一项就是“点照片回到现场”要用的数据：读回位置、朝向和焦段，再切回当时的时段和天气。

### 3.3 打卡点做成“纪念章”（玩法建议）
- 日本车站有“駅スタンプ”（车站纪念章）文化，和东京题材契合，也不涉及寺社的御朱印。
- 判定思路：取景时检查地标包围盒中心是否在视锥里（`Frustum.containsPoint`）、有没有被挡住（射线检测）、占画面多大。合格就盖一枚章，给出“好构图”的反馈。
- 章的样式沿用海报里的红印章（`poster/make_poster.py` 的 `seal()`，已经有印泥斑驳效果），每个打卡点用一个虚构图案。**不用真实品牌或车站真章的图案。**
- 3 个打卡点对应首发要求的 3 个推荐机位，由 B 给出坐标。

### 3.4 相册
- 拍完后照片像拍立得那样慢慢显影，用 CSS 动画实现。
- 相册看大图用 PhotoSwipe（见第 4 节）。
- 回忆卡选图：选 1—3 张；改选只换图片，不改照片的拍摄元信息（`agent-handbook.md` 5.3 节）。

### 3.5 回忆卡：沿用海报的视觉语言
`poster/make_poster.py` 和 `poster/make_poster_cities.py` 已经有一套成形的设计，建议回忆卡和它保持一致，让海报和游戏看起来是一个作品：

| 元素 | 海报里的值 / 函数 |
|---|---|
| 纸色 | `PAPER = (238, 232, 220)`，加高斯颗粒（`paper()`） |
| 墨色 / 灰 / 朱红 | `INK = (29, 26, 23)`、`GREY = (120, 112, 102)`、`RED = (178, 52, 40)` |
| 字体 | 思源宋体 Heavy 做标题，Noto Serif SC 可变字重做正文 |
| 版式 | 顶部 `CIJIAN` + 英文副题 + 细横线；居中加字距的大标题（`text_c()`）；照片带柔和投影（`framed()`）；右下角红印章（`seal()`） |

做法：把 `paper()`、`text_c()`、`seal()`、`framed()` 用浏览器 Canvas 2D 重写一遍，几十行即可。卡面建议放：1—3 张实拍、一行“时间 · 天气 · 地点 · 傍晚的选择”、集到的纪念章。导出 PNG 下载。

**字体注意：** 中文字体整包有几十 MB，要用 fonttools 的 `pyftsubset` 只保留卡片会出现的字，再用 `FontFace` 加载完成后才画卡片，否则会退回系统字体。两款字体都是 SIL OFL 许可，可以随网页分发，但要在 `THIRD_PARTY_NOTICES.md` 登记。

## 4. 可以直接用的开源项目

**这一节的库都是凭已有了解列出的，版本和许可还没有逐个上网核对。接入前请看各自仓库的 LICENSE 和最新版本说明，并登记进资产表。**

| 项目 | 许可 | 用途 | 备注 |
|---|---|---|---|
| **pmndrs/postprocessing** | MIT | 首选后期：景深、`LUT3DEffect` 胶片风格、暗角、颗粒、色差，多个效果合成一次渲染 | 只依赖 Three.js，不换技术栈。r160 和 r170 都应能用，需核对 peerDependencies |
| Three.js 自带扩展：`BokehPass`、`LUTPass`、`LUTCubeLoader`、`OutputPass` | MIT | 零新依赖的备选 | 画质比上一项差一档 |
| **idb-keyval** | Apache-2.0 | 用 IndexedDB 存照片 Blob 和元信息 | 很小，接口只有 get/set/del |
| **PhotoSwipe v5** | MIT | 相册看大图 | 手势、缩放、动画都成熟 |

**只借鉴设计、不拿代码：** TOEM（拍照解谜的手感）、Umurangi Generation（取景界面和胶片感）、Pokémon Snap（构图打分）、对马岛之魂的拍照模式（滤镜和景深），以及富士的胶片模拟色调。不照搬它们的 UI 和美术。

**不建议：**
- 用 html2canvas 截 3D 画面，容易黑屏或发糊。卡片直接用 Canvas 画，也用不到它。
- 直接用网上流传的胶片 LUT 包，很多许可不清楚。建议拿 Cycles 离线渲染图和例图对照，自己调色后导出 `.cube` 文件，风格也是自己的。

## 5. 和现有工程衔接要注意

以商店街网页 `projects/tokyo-market/web/viewer.js` 为例（Three.js 0.160，CDN 加载）：

- **色调映射：** 第 14 行用的是渲染器自带的 `ACESFilmicToneMapping`。改用 pmndrs/postprocessing 后，要把渲染器的 `toneMapping` 设为 `NoToneMapping`，改在效果链最后用 `ToneMappingEffect`，否则颜色会被处理两次、发灰。用 Three.js 自带的 `EffectComposer` 时，最后要接 `OutputPass`。
- **阴影：** 代码里阴影是按需刷新（`shadowDirty`）。离屏截图前要确认阴影已经是最新的。
- **相机：** 第 195—220 行有 `walk` 和 `main` 两种机位，`main` 会按例图竖幅改 `fov`。取景模式要单独保存和恢复 `fov`、`near`，不要和这两种模式互相覆盖。
- **两套工程未统一：** 商店街是 r160，台阶样板是 r170。拍照模块建议写成独立文件，只依赖 `renderer`、`scene`、`camera` 三个对象，以后合并工程时直接挪过去。
- **坐标：** 商店街注释写明 Blender `(x, y, z)` = three `(x, z, -y)`。打卡点坐标由 B 在 Blender 里给出时，要按这个换算。

## 6. 建议的研究和实现顺序

1. **最短闭环先跑通**（不等地点确定）：在商店街页面加取景模式 → 离屏截图 → 存进 IndexedDB → 下载 PNG。验收标准是**打开下载的文件**，确认画面、时段正确，没有 HUD。
2. 用最简版式把 1 张照片合成回忆卡并导出，先不做美化。这一步对应规划里的 G2 关口。
3. 加后期：景深和 1—2 种胶片风格，在游戏本上有窗口实测帧率，确认进入取景模式时不掉帧太多。
4. 回忆卡套用海报视觉语言，加字体子集。
5. 地点确定后：B 给出 3 个打卡点坐标，做集章判定和纪念章图案。
6. 最后做“点照片回到现场”和快门转场。

每一步完成后，在 `docs/STATUS.md`（如还没建，就先建）记下做到哪、改了哪些文件。

## 7. 风险

- **后期效果开销：** 景深和多重后期在 5070 上应该没问题，但还没实测。建议只在取景模式里开景深，走路时关掉。
- **离屏大图读回：** 约 3000×2000 的 `readPixels` 和 PNG 编码可能卡顿零点几秒。用快门动画盖住；如果仍然明显，改用 `toBlob` 异步编码或降到 2400 宽。
- **存储空间：** 每张 PNG 可能几 MB。建议存 JPEG（质量约 0.92），并限制相册张数，比如 30 张，超过时提示删除。
- **浏览器隐私模式：** IndexedDB 可能不可用。按规划要求，此时提示“无法保存”，但仍能拍照并直接下载。
- **版权：** 纪念章、招牌、卡片里不出现真实品牌、商标或车站真章图案；字体和库都要在 `THIRD_PARTY_NOTICES.md` 登记。

## 8. 不要做的事

- 不要用预制图或宣传图冒充玩家照片，截图失败时显示原因并让玩家重试。
- 地点没定之前，不要把打卡点写死在“谷中”或“浅草”。
- 不要把“按钮能点”当成拍照完成，以下载文件为准。
- 不要把本文的建议写成团队已同意。
